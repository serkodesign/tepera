# Аналітика, рівень 1 — чекліст перевірки і декларацій (для власника)

## Ручний чекліст на пристрої (виконано на Huawei P9 26.11.2026; лишається повторний прогін на release-збірці)
Автоматично зеленими лишаються лише юніт-тести. Інструментальні тести і живу перевірку треба зробити вручну.

1. `sh gradlew :app:connectedStandardDebugAndroidTest` — `MigrationTest` (у т.ч. `migrate23to24_...`, ланцюг 17→24) і `DailyEventCounterDaoTest`.
2. Встановити збірку **поверх** наявної (`installBetaDebug`): міграція v23→v24 без падіння, дані на місці.
3. Лічильники ростуть: відкрити вкладки, додати активність, додати/змінити/видалити вікно (beta), поставити паузу воріт. Подивитись таблицю:
   `adb shell run-as com.serkodesign.tepera.debug sqlite3 databases/tepera.db "select * from daily_event_counters"` (або витягнути БД; ім'я пакета debug-збірки звірити).
4. Не повинно бути: назв застосунків, тексту, `package` у `eventName`/`propsKey`.
5. Екран «Поділитися анонімною статистикою» (Налаштування → Дані й приватність): текст у блоці = текст у листі; кнопка неактивна без подій; без поштового застосунку — тост, а не падіння; `stats_share_opened` росте при відкритті, `stats_shared` — лише після відкриття вибору застосунку.
6. «Видалити всі дані»: таблиця порожня після перезапуску.
7. Очищення: `AnalyticsCleanupWorker` у `adb shell dumpsys jobscheduler | grep analytics_cleanup` — заплановано; перевірити видалення, вставивши рядок із датою старше 90 днів і запустивши воркер (`adb shell cmd jobscheduler run ...`) або тимчасово змінивши поріг у debug.
8. Онбординг (чиста установка): `onboarding_started`, кроки, `onboarding_completed` за один прохід; `usage_access_granted` — після надання доступу; `accessibility_service_enabled` — після ввімкнення служби (beta).
9. Beta, годинa скролінгу: відкрити стрічку у вікні → `risk_window_started` один раз за добу, `intention_sheet_shown` кожен раз; «Так, роблю це» → `intention_selected [bucket=...]`; задачки → `puzzle_shown/solved/abandoned`; «Відкрити на 5 хв» → `soft_exit_shown`, потім `soft_exit_outcome`.
10. Англійська й українська локаль екрана «Поділитися…» (рядки є, на екрані не дивились).

## Відомі обмеження (прийнято)
- «Онбординг завершено» = вихід на Home (рахується і «Пропустити все», і повторно відкритий крок).
- `tab_viewed` — кожне повернення на екран, не унікальні перегляди.
- `widget_added` — лише перший екземпляр кожного типу віджета.
- `IdeaHero` на Головній не дає `intention_selected`.
- `risk_window_started` — раз на вікно за добу в межах життя процесу сервісу (після перезапуску процесу може порахуватись ще раз).

## Data safety (Play Console) — відповіді для рівня 1 (D2, рекомендація: так, обережно)
| Пункт | Відповідь |
|---|---|
| App activity → App interactions | Collected · Optional · Purpose: Analytics |
| Shared with third parties | No |
| Encrypted in transit | Лист користувач надсилає сам своїм поштовим застосунком — відповідь вибрати за поточним формулюванням форми (вона вимагає «так/ні» для передачі з пристрою); за умовчанням «Yes» нема підстав стверджувати — звірити формулювання у формі |
| Users can request deletion | Yes — див. об'єднану таблицю в `play-console-declarations.md` (розділ «Data safety: підсумок рівнів 1+2») |
| Collection optional | Yes |

Примітка: Google може вважати дані, які людина сама надсилає листом, такими, що «не збираються застосунком».
Декларація «Collected · Optional» — обережніший варіант (за планом, D2). Остаточне рішення — за власником.
Інші розділи Data safety (crash logs, мережеві дозволи, Remote Config) цією фічею не змінюються.
