## 3. Історичні рішення продукту (коротко, з причинами)

**Відхилені назви:** LifeBalance/Life Balance, Tysh, Roots/Rooted, Ballast, Haven, Anchorage, Foothold, Sundial, Meridian, Equinox, Presently, Nyni, SideQuest, Teper, Cushion, Opora — зайняті або з небажаними асоціаціями.

**Скасовані елементи продукту**
- Автозупинка таймера через 4 год → замінена одним сповіщенням «усе ще цим займаєшся?» (FR-4.7): автозупинка створювала записи «тривалість під питанням».
- «5-й слот» віджета (підказка про давно не логовану категорію) — прибрано: усі неактивні кнопки однакові (FR-4.6).
- Метрика «твій день з телефоном» — прибрана (FR-D.6): назва бреше, число велике без важеля впливу.
- Постійний показ «востаннє брав телефон» на Home — скасовано (FR-D.7): порушував принцип пасивного сорому.
- Категорія «Сон» у логуванні — прибрана (v2.4).
- Перемикач «Місяць» у Статистиці — прибрано (FR-5.2).
- Топ застосунків за Online — свідомо не робимо (найближче до «оцінки»).
- Візуальний «стек» карток з перекриттям із макета Figma — не робимо.
- Заглушка «Pro (скоро)» — не робили; для бази знань те саме рішення поширене в D-05.
- Питання про цінності в онбордингу (FR-P.2) — скасовано (D-11): відповідь ніде не використовувалась.

## 4. Технічні пастки й уроки (виведено з вимог)

Раніше лежали всередині FR-рядків; тут вони, щоб не забути, але не засмічувати специфікацію.

- **Online через бакети завищує.** `queryUsageStats(INTERVAL_DAILY)` рахує цілі бакети й для часткової доби давав 159 хв проти 47 хв у Digital Wellbeing. Рішення — сирі `UsageEvents` (FR-3.1). Лаунчер і клавіатуру виключати динамічно, не хардкодом пакетів.
- **Room без міграції.** Зміна схеми без bump версії падає з `IllegalStateException` (відтворено на S23 при `adb install -r`). Завжди bump + `Migration`, `fallbackToDestructiveMigration` не використовувати.
- **Віджет: одночасні важкі запити.** Після скидання кешу всі екземпляри віджета запускали важкі запити подій; одне оновлення впало з binder-помилкою `UsageEvents`. Розрахунок сітки тепер один на всіх (mutex) із запасним варіантом.
- **Перехід о 01:00.** Разове точне завдання WorkManager; Doze може зсунути на кілька хвилин. Живої зміни доби не спостерігали (V-02).
- **Glance.** Реальну висоту не повідомляє (`LocalSize` — найближчий менший розмір зі списку); RemoteViews губить зайві діти контейнера; 1x1 на Samsung — лише 76dp; `cornerRadius` з API 31. Звідси: сітка доби однією Bitmap, кругле тло drawable-ами.
- **Закріплені ярлики.** Android не дозволяє знімати закріплення; повторне створення з тим самим ID не показує діалог розміщення — тому кожне створення має свіжий `shortcutId`. `requestPinShortcut()`/`requestPinAppWidget()` — на диспетчері виклику, не на IO. Іконка з кільцем по краю зникала в діалозі пінування — бейдж-куточок у безпечній зоні.
- **`singleTask` + `onNewIntent`.** Без цього повторний тап у фоні не доставляв нових extras на екран паузи.
- **Анімація на P9.** «Миготіння» екрана паузи було зумовлене `Animator duration scale = 0` на тестовому P9 — налаштування пристрою, не баг застосунку.
- **`KEYGUARD_HIDDEN`** — API 28+; нижче функція приховується, без апроксимації (людина порівняє число з відчуттям і перестане довіряти).
- **Локаль.** `AppCompatDelegate` для мови працює лише з `AppCompatActivity`; тому власне обгортання контексту через `SharedPreferences` для синхронного читання в `attachBaseContext`.
- **Часовий пояс.** 25-годинна доба (25.10.2026) і 23-годинна (29.03.2026, Europe/Kyiv) покриті юніт-тестами.
- **Показ системної історії обмежений** ~7–9 добами: старіші дні без даних не показуємо (нуль був би хибним фактом).
- **`SleepWindowCalculator.isInsideWindow()` завжди повертав `false` (знайдено при написанні юніт-тестів вікон сну, виправлено).** Точкова перевірка йшла через `minutesInWindows()`, який округлює інтервал у 1 мс до 0 хв. Наслідок: нічні розблокування у вікні сну (FR-3.5, FR-D.13) враховувались у старті дня, лічильнику розблокувань і хронології «Вчора». Після виправлення число розблокувань може зменшитись, і це правильно. Урок: арифметика вікон мусить мати тести (FR-3.2) — саме вони це знайшли.
- **Багатодобовий запис і доба.** Розрахунки відносять запис до доби за `startTime`, а Home бере записи від початку логічної доби (01:00). Тому ділимо активність по 01:00, а не по 00:00 (D-14): інакше частина, що починається о 00:00, не потрапляла б у сьогоднішній Home. Обмеження: тап-таймер, що йде через 01:00, досі зберігається одним записом.
- **Експорт JSON.** Реальний склад: категорії, записи (з `seriesId`), виключені застосунки, орієнтир. Вікна сну, паузи, ворота й решта налаштувань не переносяться. SRS v4.0 помилково писала, що орієнтир не входить у файл (виправлено в v4.1).
- **Lint і плитка швидких налаштувань.** Lint скаржиться (`StartActivityAndCollapseDeprecated`) на гілку для API < 34, хоча на API 34+ код уже використовує `PendingIntent`. Це хибне спрацювання, не баг. Lint має ще ~10 помилок, які були до ребілду (`LocalContext` не враховує конфігурацію, `FlowOperatorInvokedInComposition`); релізну збірку це не блокує, але варто розібрати.
- **Vibecoding-пастка:** LLM охоче пише код, що читає дані Screen Time на iOS; він компілюється й мовчки нічого не повертає. Стосується майбутнього iOS-проєкту.

Не робити зараз (заморозка), але зробити першими, якщо тест покаже, що функція не використовується:
