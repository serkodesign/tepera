# ЧЕРНЕТКА — аналітика рівня 2 (PostHog): політика, Data safety, магазин (НЕ опубліковано)

Статус: чернетка для власника, 26.11.2026. Нічого не опубліковано. Політику на GitHub Pages, Data safety і лістинг у Play
Console оновлює власник вручну. **Потрібне лише коли випускається збірка з ключем PostHog** (без ключа в збірці віддаленої
аналітики нема взагалі, а UI згоди прихований). Ухвалені за замовчуванням рішення плану: D1 = opt-in, D3 = GeoIP вимкнено,
D4 = події категорії B лише локально, D5 = EU (Франкфурт).

## 1. Що саме надсилає збірка з ключем (перевірено на P9 по вмісту черги SDK)
Лише після явного «Так». Кожна подія — одна з категорії A (власний інтерфейс: онбординг, вкладки, додано активність/вікно,
пауза воріт, віджет…, див. `analytics/AnalyticsEvent.kt`) з властивостями лише з allowlist (`tab`, `step`, `duration`,
`enabled`, `bucket`, `outcome`, `type`, `widget`, `is_first`) + `app_version`. Події категорії B (похідні від служби доступності
й доступу до статистики використання: показ листа поверх стрічки, наміри, задачки, м'який вихід) **не надсилаються** — лише
локально. Без назв/пакетів застосунків, без тексту користувача, без точних тривалостей, без вмісту екрана.

**Службові властивості, які додає сам SDK PostHog (їх теж треба декларувати/згадати):** модель і виробник пристрою, версія й
назва ОС, версія й збірка застосунку, мова (`$locale`), часовий пояс, розмір і щільність екрана, тип пристрою, ознака
«встановлено не з магазину» (`$is_sideloaded`), user-agent, `$session_id` (випадковий, лише на сесію застосунку),
випадковий анонімний `distinct_id`. Профілі людей вимкнені (`$process_person_profile=false`, `$is_identified=false`),
`identify()` ніде не викликається, GeoIP вимкнено на кожній події (`$geoip_disable`), запис сесій/автозбір/опитування/remote
config вимкнені. **Окремо на боці PostHog треба ввімкнути «Discard client IP data» в налаштуваннях проєкту EU.**

## 2. Що змінити в політиці (docs/privacy-policy.md)
Зараз політика каже, що Tepera «offline-first» і «не збирає ... даних» (UA рядок 13; EN рядок 72) та що «сама Tepera
нічого не надсилає» (UA 22; EN аналогічно), а «Tepera його нікуди не надсилає» (UA 30) стосується файлу експорту — це лишається
правдивим. Зі згодою на рівень 2 перші два твердження стають неточними: застосунок надсилає анонімні події. Треба:
1. Замінити «Ми не збираємо ... будь-яких даних» на формулювання, що **без вашої згоди нічого не збирається, а за згодою —
   анонімна аналітика (розділ нижче)**. Лишити «offline-first» (основний функціонал працює без мережі).
2. Прибрати/уточнити «сама Tepera нічого не надсилає» (Auto Backup-абзац): додати «окрім необов'язкової аналітики за вашою
   згодою та звітів про збої, які можна вимкнути».
3. Додати розділ з 8.2 нижче. Оновити дату «Останнє оновлення».
4. Блок про Accessibility не змінюється (дані служби не йдуть назовні: D4 = ні).

### Текст розділу
Актуальний текст (УКР + EN) уже внесено в `docs/privacy-policy.md`, розділ «Продуктова аналітика» / "Product analytics": вимкнено за
замовчуванням; запит після першого досвіду й один повтор через ~30 днів після «Не зараз»; кнопка «Видалити мої дані аналітики»
(вимкнути + скинути ID + готовий лист із ID); зберігання подій до 12 місяців; обробник PostHog (ЄС). Ті самі твердження мають
збігатися з рядками `analytics_consent_*` / `analytics_delete_*` у застосунку.

> Примітка: формулювання щодо GDPR (правова підстава — згода, право на видалення, міжнародна передача) варто звірити з
> шаблоном або юристом.

## 3. Лістинг у Play (docs/store-listing-en.md рядок 49, store-listing-ua.md рядок 49)
Зараз: «usage statistics are processed on your device and Tepera does not send them anywhere ... Tepera itself sends nothing» /
«Tepera не надсилає її нікуди». Для збірки з рівнем 2 замінити, напр.:
- EN: «🔒 **Privacy** — your entries stay on your device. Optional anonymous usage analytics (off until you turn it on) and optional crash reports can be switched off in Settings → Data and privacy. No accounts, no ads, no social feed.»
- UA: «🔒 **Приватність** — ваші записи лишаються на пристрої. Необов'язкова анонімна аналітика (вимкнена, доки ви не ввімкнете) і необов'язкові звіти про збої вмикаються й вимикаються в Налаштування → Дані й приватність. Жодних акаунтів, реклами чи соціальної стрічки.»
Рядок 53 про Accessibility («Tepera does not send this data anywhere») лишається правдивим (D4 = ні).

## 4. Data safety (Play Console) — відповіді після рівня 2
Оновити **до** викочування збірки (декларація має покривати всі версії в Play).
| Пункт | Відповідь |
|---|---|
| App activity → App interactions | Collected · Optional (opt-in) · Purpose: Analytics |
| Device or other IDs | Collected · Optional · Analytics (анонімний випадковий ID PostHog) |
| App info and performance → Crash logs | Collected · Optional · App functionality/Analytics (Crashlytics, як і зараз; не змінюється) |
| Approximate location | **Ні** (GeoIP вимкнено і на події, і треба вимкнути/відкинути IP в проєкті PostHog) |
| Device model, OS version, language, time zone | Входять до «Device or other IDs»/діагностики; перевірити формулювання категорій у формі («Device or other IDs» — найближча) |
| Shared with third parties | No (PostHog — постачальник послуг/обробник) |
| Encrypted in transit | Yes (HTTPS) |
| Users can request deletion | Yes — кнопка «Видалити мої дані аналітики» в застосунку (скидає ID) + готовий лист із ID для стирання подій у PostHog |
| Collection optional | Yes — користувач може відмовитись у застосунку |
Рівень 1 (лічильники на пристрої, «Поділитися листом») — як у `docs/analytics-level1-checklist.md`; обидва рівні разом
декларуються як «App interactions».

## 5. Перед релізом (робить власник)
1. Створити проєкт PostHog **EU**; увімкнути **Discard client IP data**; GeoIP-трансформацію вимкнути.
2. Отримати ключ `phc_...` → у `local.properties` (`posthog.apiKey=...`) на машині, що збирає реліз. Збірка без цього рядка —
   без віддаленої аналітики (NoOp). **Не збирати debug/тестові збірки з бойовим ключем** — забруднять метрики.
3. Опублікувати політику (розділ 2), оновити Data safety (розділ 4) і лістинг (розділ 3) — **до** викочування.
4. Декларація Accessibility — без змін (D4 = ні).
5. Реліз спершу в Open testing, потім Production.
6. Реальна перевірка надходження подій у PostHog (ключ потрібен; на тестовому P9 мережі не було — перевірено лише чергу
   SDK: події в потрібному вигляді, до згоди запитів нема).
