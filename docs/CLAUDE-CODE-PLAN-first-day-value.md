# План: цінність у перший день, без «тижня тиші» (23.11.2026)

Статус: **ПЛАН, код не чіпали.** Режим годин скролінгу (flavor `beta`, `BuildConfig.V3_MVP`); `standard` не змінюється.
Гіпотеза власника: люди відвалюються, поки застосунок «вивчає» користувача. Це гіпотеза, не факт — див. крок 0.

## Що вже є в коді (звірено 23.11.2026)
- Історію беремо з системи: `UsageSlotRepository.recompute()` перераховує слоти за **останні 10 днів** із `UsageEvents`, тож тиждень не треба «збирати з нуля».
- Період спостереження (`observation_period`) створює перший скан, коли покрито ≥ `RiskConfig.minObservedDays = 7` завершених логічних діб. Рахуються лише доби, де покрита і сама доба, і наступна (`RiskHomeViewModel` ~134), а перша доба після найранішої події відкидається (`UsageSlotRepository` ~66) → потрібно **≈ 8–9 діб системної історії**.
- Отже, на телефоні з ≥ 9 днями історії тижня тиші немає взагалі. Чекають лише пристрої з коротшою історією (старі Android, нещодавно скинуті).
- Тиша (нема `observation_period`): без листа плану поверх стрічки і без нагадувань (`NudgeScheduler` ~54, коміт `ccdf38d`). Рішення власника.
- Уже є на екрані спостереження (`RiskHomeScreen.ObservingContent`/`ObservingHeat`): смужка «День N з 7», текст «Нічого робити не треба», картка «Не хочеш чекати? Обери години сам», теплова карта (**нижче** карток), підказка `v3_teaser_format` від 3 днів (`TEASER_MIN_DAYS`), Online сьогодні.

Висновок: пункти 3, 5, 6 з обговорення частково готові, пункт 4 може бути зайвим. План нижче — доробка, а не новий розділ.

## Фаза A (пункти 1–3 з обговорення, один тікет, без зміни продуктових правил)
Ціль: у перші секунди після дозволу людина бачить **свої** дані і розуміє, що відбувається.

**A1. «Твої стрічки за N днів» одразу.** Новий чистий `domain/risk/HistorySummary` (середні хв/день у стрічках за покриті доби, годинний пік, `coveredDays`) + юніт-тест (за зразком `RiskWindowFinder`-тестів). Рахується з `records`, які `RiskHomeViewModel.refresh()` уже читає. Показується від **1 покритої доби** (зараз підказка лише від 3).
**A2. Тиша ≠ порожньо.** `ObservingContent`: картка підсумку з A1 — **угорі**, під смужкою прогресу; `ObservingHeat` піднімається вище за карусель годин. Текст `v3_observing_hint` і `tutorial_observing_body` переписати: що саме відбувається («ще N дн. дивлюсь на твою історію, нічого не перериваю — щоб було з чим порівняти») замість «тиждень вивчає». N = 7 − `observedDays`.
**A3. «Точка відліку» зразу.** Те саме число з A1 під назвою «Твоя точка відліку», **та сама формула**, якою потім рахуватиме `WeekCard` (`baselineMinutes`), щоб число не змінилося пізніше без причини. Через тиждень `WeekCard` порівнює з нею.

Файли: `RiskHomeViewModel.kt` (стан `historySummary`), `RiskHomeScreen.kt`, нові рядки uk+en (`values/` і `values-uk/`), тест.
Правила подачі: лише власні дані, число з контекстом («середнє за N дн.»), без оцінок, кольорів «добре/погано», без порівняння з нормою (FR-P.3–P.6). Увага: це числа, що можуть засмутити (ТЗ 2.2) — для режиму годин власник уже дозволив такі на Головній; підтвердити для екрана спостереження.
Приймання: свіже встановлення з історією 3 дні → одразу видно підсумок і точку відліку; з 0 днів → чесний порожній стан без числа; з ≥ 9 днями → екрана спостереження немає; uk/en; темна/світла тема; шрифт 130%.
Оцінка: ~1 сесія.

## Фаза B (решта пунктів)
**B1. Дія з даних одним тапом (пункт 5).** До картки-підказки `v3_teaser_format` (і до підсумку A1) кнопка «Зробити годиною» для знайденого піку: створює ручне вікно існуючим шляхом `RiskWindowRepository` (~рядок 93). Людина отримує робочу годину в першу хвилину, і дані не псуються (вікно ручне; період спостереження не створюється — тиша для базових вікон лишається). Існуючу картку «Обрати години» залишити як запасний шлях.
**B2. Щось «живе» без даних (пункт 6).** У стані спостереження показати «Замість скролу» (`SuggestionPicker`, «Інша ідея»), бо зараз там лише Online. Додати «у стрічках сьогодні» чипом (з тих самих слотів).
**B3. Пропозиція під час онбордингу (за потреби).** Після вибору стрічок показати A1/B1 одразу, а не після закриття туторіалу (`HOME_TUTORIAL` стартує через 1,5 с — перевірити, що не перекриває).
Оцінка: B1 ~0,5 сесії, B2 ~0,5, B3 ~0,5.

## Фаза C (змінює продуктове правило — лише після закритого тесту і рішення власника)
**C1. Коротший період (пункт 4).** Знизити `minObservedDays` з 7 до 5–6. Ціна: гірша база порівняння (будні/вихідні), `RiskWindowFinder` вимагає повторюваності «в N з observationDays днів» — перевірити пороги й тест `RiskWindowFinder`. Потрібне явне «так» власника: це скасовує «тиждень = тиша».
**C2. «Попередні вікна».** Від 3–4 днів показувати знайдене вікно як «попереднє» й дозволити людині ввімкнути оверлей для нього свідомо. База порівняння частково псується — рішення власника.
