---
name: save
description: Зберегти проєкт у git — коміт і push поточної гілки, щоб продовжити роботу на іншому пристрої. Використовуй, коли власник пише "збережи проект в гіт", "/save" або схоже.
---

1. `git status` і `git diff --stat` — подивись, що змінилось.
2. Додай у індекс лише відстежувані зміни (`git add -u`) та нові файли, які явно належать до роботи
   (код, ресурси, docs). Неіндексовані великі/релізні артефакти (`release/`, `*.zip`, `*.aab`, `*.apk`,
   скріншоти) і все, що схоже на секрети (`local.properties`, keystore, `.env`, `google-services.json` якщо не був у git),
   НЕ додавай — перелічи їх у відповіді й спитай, чи потрібні.
3. Коміт із коротким осмисленим повідомленням (за змістом змін, мовою попередніх комітів), з рядком
   співавторства з системного нагадування.
4. `git push` (якщо в гілки немає upstream — `git push -u origin <гілка>`). Жодного `--force`.
5. Якщо push відхилено (гілка позаду) — не форсуй: покажи ситуацію й запропонуй `git pull --rebase`.
6. У кінці: гілка, хеш коміту, що не потрапило в коміт, і нагадування, що пам'ять Claude (`~/.claude/.../memory`)
   і `local.properties` через git не переносяться.
