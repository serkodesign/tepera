# ROADMAP — Tepera (v2.8)

Розбивка фаз із SRS v2.0 (розділ 7) на конкретні задачі, Фази 0-6 нижче ще написані до
переосмислення ядра в SRS v2.2-v2.5 (лишені як історія — самі задачі виконані, лише термінологія
застаріла: "Online/Offline баланс" → "Структура доби", "Сон" був серед дефолтних категорій).
Актуальний стан ядра — розділи "SRS v2.5 rebase", "SRS v2.6 rebase", "SRS v2.7 rebase" і
"SRS v2.8 rebase" нижче.
Працювати по одній фазі за раз. Позначай `[x]` по завершенню.

## Фаза 2 — Online/Offline баланс (~3 тижні)
*(нова фаза замість Health Connect/Sleep API з v1.5)*
- [x] **Спайк:** перевірено на реальному пристрої (Samsung S23, Android 16). `queryUsageStats()`
      справді повертає імена пакетів незалежно від package visibility filtering (окремий
      AppOps-грант, не PackageManager query), але резолвити людську назву/іконку через
      `getApplicationInfo()` без додаткової видимості НЕ вдалося — 226 із 580 пакетів, побачених
      за 30 днів, кидали `NameNotFoundException`, включно з реальним застосунком (Pocket Casts).
      Друга проблема: без фільтрації "580 пакетів" — це здебільшого системний шум
      (drivers/RRO-оверлеї), не реальні застосунки. **Рішення без QUERY_ALL_PACKAGES:**
      `<queries>` з intent-фільтром MAIN/LAUNCHER у маніфесті — не вважається чутливим дозволом
      при Google Play review (на відміну від QUERY_ALL_PACKAGES), відсікає системний шум і
      повертає видимість усіх launchable застосунків. Після фіксу: 113 релевантних застосунків,
      0 unresolved. Exclusion List будується саме так.
- [x] Онбординг-екран з поясненням, навіщо потрібен доступ до статистики використання —
      показується автоматично один раз (DataStore-прапорець), перевірено вживу
- [x] Інтеграція UsageStatsManager, читання Online-часу за добу — перевірено вживу з реальними
      даними після надання доступу
- [x] Grace Period Buffer формула, скидання о 00:00 — перенесено з Фази 0 (BalanceRepository),
      маркер таргету на шкалі відображається коректно
- [x] Налаштування таргету (дефолт 180 хв) — SettingsStore (DataStore), екран Налаштувань
- [x] Exclusion List — вибір застосунків зі списку встановлених — перевірено вживу (Карти,
      увімкнення/вимкнення перемикача переживає перезапуск)
- [x] Fallback UI без наданого дозволу — картка балансу на Home показує заклик до дії, поки
      доступ не надано; офлайн-логування (Фаза 1) увесь час лишається робочим
- [x] **Крашфікс:** `queryUsageStats()` кидає `SecurityException` (не повертає порожній список,
      як припускав коментар у коді), якщо доступ був наданий, а тоді вимкнений вручну в
      Налаштуваннях — застосунок падав замість показу fallback. Відтворено на реальному
      пристрої через `adb shell appops set ... android:get_usage_stats deny`; `hasUsageAccess()`
      і `getOnlineMinutes()` у `BalanceRepository` тепер ловлять `SecurityException`
- [x] **UI-покращення (за запитом):** картка балансу — два окремі підписані пропорційні бари
      (Online/Offline зі своїми хвилинами), а не одна шкала без явного відображення Offline;
      маркер таргету лишився на Online-барі. Перевірено вживу
- [x] **Багфікс (за запитом):** `getOnlineMinutes()` через `queryUsageStats(INTERVAL_DAILY, ...)`
      завищував Online-час (159 хв у Tepera проти 47 хв у системному Samsung Digital Wellbeing за
      той самий момент) — межі бакетів статистики не обрізані рівно по `[from, to]`. Замінено на
      підрахунок по сирих подіях `UsageEvents` (MOVE_TO_FOREGROUND/MOVE_TO_BACKGROUND), обрізаних
      точно по запитаному інтервалу — той самий підхід, що й системні лічильники екранного часу.
- [x] **UI-покращення (за запитом):** картка балансу на Home перероблена під стиль віджета — один
      сумісний бар (Online-частка + Offline-частка на одній лінії) з відсотками над ним
      ("Online: 43% · Offline: 57%") замість двох окремих шкал.
- [x] **Багфікс (за запитом):** лаунчер і клавіатура виключені з підрахунку Online-хвилин за
      замовчуванням, поверх ручного Exclusion List — визначаються динамічно через
      `PackageManager`/`InputMethodManager`, не захардкоджені пакети. Перевірено вживу на
      Samsung S23: 67 хв → 59 хв за той самий момент після виключення.

## П'ять виправлень і доробок за прямим запитом користувача (не з tepera-dev-spec.md)

- [x] **Ворота: "Не зараз" повертає на робочий стіл, не на внутрішній екран Tepera.** Раніше
      `GatePauseScreen.onDone` робив лише `navController.popBackStack()` — якщо ворота
      відкрились, поки застосунок уже стояв на ІНШОМУ екрані (напр. `GatesScreen`), один крок
      назад повертав саме туди, а не на робочий стіл, як мало б бути для "тонкого шлюзу".
      Фікс — два незалежні кроки: `onDone` тепер `popBackStack(Routes.HOME, inclusive = false)`
      (чистить будь-що між Home і GATE_PAUSE), і одразу після нього `GatePauseScreen` викликає
      `(context as? Activity)?.moveTaskToBack(true)` — застосунок іде у фон, користувач бачить
      лаунчер, а не Tepera. Застосовується однаково для "Не зараз" і для автозапуску таймером —
      обидва шляхи ведуть через `state.finished`.
- [x] **Ворота: видалення ярлика з робочого столу видаляє рядок і зі списку в застосунку.**
      Android не дає колбек на видалення pinned shortcut (спільний для всіх лаунчерів API
      відсутній) — `GateRepository.pruneRemovedShortcuts()` (новий метод) звіряє
      `ShortcutManager.pinnedShortcuts` із рядками `app_gates` і видаляє ті, чийого ярлика вже
      немає серед закріплених. Викликається on-demand при кожному відкритті `GatesScreen`
      (`GatesViewModel.init`, той самий патерн, що сканування пауз/патерну — не фонова задача).
- [x] **Нотатка запису (FR-1.1) тепер виводиться, не лише вводиться.** `HistoryEntryRow`
      (StatsScreen, картка "Історія") показувала лише категорію й час — поле `note`, яке заповнює
      `AddEntryScreen`, ніде не відображалось. Додано третій рядок (bodySmall, приглушений колір,
      maxLines = 2), лише коли нотатка не порожня.

      `CategoryDao.hardDeleteNotUsedInMvpUi()` існував у схемі, але не викликався з UI (коментар
      прямо це забороняв). За запитом користувача тепер викликається — але СВІДОМО ЛИШЕ для
      `isCustom = true`: дефолтні категорії пересіваються щозапуску за фіксованим id
